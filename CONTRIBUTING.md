# Contributing Policy

## 1) Policy по PR-процессу

### 1.1 Маленькие PR
- Держите PR сфокусированным на одной задаче.
- Рекомендуемый размер: до ~300 строк изменения (по возможности).
- Крупные изменения делите на последовательные PR (refactor → feature → docs).

**Зачем:** проще ревью, меньше риск регрессий, быстрее merge.

### 1.2 Осмысленные commit-сообщения
- Используйте формат: `<type>: <short summary>`.
- Примеры `type`: `feat`, `fix`, `docs`, `style`, `chore`, `refactor`.
- В тексте summary отвечайте: *что изменено* и *где*.

Пример:
- `fix: correct viewport meta and semantic sections in index.html`

**Зачем:** понятная история изменений и удобный поиск по git log.

### 1.3 Краткое описание «что/зачем» в PR
Каждый PR должен содержать минимум:
- **Что сделано** (списком);
- **Зачем сделано** (какую проблему решает);
- **Как проверялось** (команды/результаты).

**Зачем:** ускоряет ревью и снижает число уточняющих вопросов.

---

## 2) Definition of Done (DoD)

Задача считается завершённой только если одновременно выполнены все условия:

1. **Код работает**
   - Изменение функционально корректно и не ломает существующее поведение.

2. **Проверки зелёные**
   - Локально пройдены релевантные проверки (`lint`, `format:check` и др.).
   - CI-проверки в PR успешны.

3. **Документация обновлена**
   - При необходимости обновлены `README.md`, `CHANGELOG.md` и/или другие профильные документы.

Если хотя бы один пункт не выполнен — задача не готова к merge.
